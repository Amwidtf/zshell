# 安全说明（Security）

## 报告漏洞

请勿在公开 Issue 中提交安全漏洞细节。请通过 GitHub 仓库的 **Security Advisories（Report a vulnerability）** 提交，或联系维护者。我们会在确认后尽快修复并在致谢中感谢报告者（如你愿意）。

## 安全模型

### 凭据存储

- 配对凭据（`sid` + `hash`）通过 MMKV **AES 加密**存储，加密密钥由 **Android Keystore** 托管（不落明文文件）；
- 应用锁（指纹 / 人脸 / 图案 / 密码）在应用打开与后台恢复时强制验证，验证器为 PBKDF2-HMAC-SHA256（随机盐 + 20000 次迭代 + 常数时间比较），不存储明文秘密。

### 信任边界（使用者须知）

1. **配对 URL 即长期凭据**：拿到配对链接的任何人都能连接你的桌面端。请勿在不受信任的渠道传播；建议定期在桌面端执行凭据轮换（轮换后在本应用重新扫码即可，机器记录会自动合并）。
2. **中继链路**：远程会话经官方中继服务传输，本软件不新增暴露面，也无法提供端到端加密。敏感代码库慎用远程控制。
3. **DSH 明文地址**：DSH（DeepSeek Harness）远程地址由使用者自建，局域网地址为明文 `http://`。应用为打开此类地址放行了明文网络访问（Android `usesCleartextTraffic`），除用户主动配对的 DSH 地址外应用自身不存在任何明文请求（ZCode / Kimi 控制台、更新检查均为 https）。请在可信网络使用，或为 DSH 配置 https 隧道。
4. **DSH 自签名证书的按机器信任**：DSH 的 https 地址常用私有 CA / 自签名证书（如 Caddy 内部 CA），系统校验必然失败。应用不会默认放行：首次连接报证书错误时弹窗征求明确同意，信任按机器记录（加密存储）、随时可在管理面板撤销；被信任的地址在连接时跳过证书校验，意味着该链路失去服务端身份验证——在不安全网络上可能被窃听或篡改，请只信任自己部署的地址。撤销信任或重新配对即恢复严格校验。该放行通过本仓库维护的 react-native-webview npm 补丁（`proceedOnSslError` 属性，默认关闭）实现，对 ZCode / Kimi 页面行为无影响。
5. **DSH 访问口令**：自建地址若被反向代理的 HTTP Basic 保护，口令在本应用内按机器加密存储（与配对凭据同库），不写入日志或诊断；WebView 会将其附加到对应该地址的请求上。
6. **第三方客户端的固有风险**：官方服务端可能随时收紧校验或变更协议，本软件可能因此部分失效。

### 已知限制（当前版本）

- 明文网络访问为全局放行（仅服务于用户主动配对的 DSH 局域网地址；Android 无法按 IP 段细粒度授权）；
- 应用锁的图案秘密空间较小（3×3 点序），已用 PBKDF2 抬高离线爆破成本，但物理接触设备者仍可尝试——更高安全需求请使用密码锁或生物识别；
- WebView 内运行的是官方网页，其自身的安全更新由官方负责。

## 漏洞披露政策

- 收到报告后 72 小时内确认；
- 修复后按严重程度决定是否发布安全公告；
- 我们不会对善意报告漏洞的研究者采取法律行动。
